# Per-chunk PGEO body breakdown (v42k7 — the bulk world data)
# Each v42k7 chunk has:
#   [0x00..0x34]  OEGP header  — version, kind, scale, world bbox, name
#   [0x34..0x60]  body header  — Table B count, Table A count, total_size,
#                                vbuf_size, section_count
#   [0x60..0x88]  name field   — Models_Ungrouped_NNNN string (40B fixed slot)
#   [0x88..]      section records — section_count × 64 bytes:
#                    +0x00..0x18   6 BE floats (local bbox)
#                    +0x1c..0x34   up to 3 (count, ptr) pairs → slot list
#                                  (1-3 rmb pool handles per section)
#                    +0x34..0x40   '(padding)' — actually 8 bytes; sometimes
#                                  contains additional handles, sometimes
#                                  coordinate-shaped floats. Heterogeneous.
#                                  ~3,576 sections have nonzero data here.
#   [after sections]  section_handles array (u32 BE handles)
#                     Table A     (8B records of (handle, pad))
#                     Table B header (16B) + 0xFFFFFFFF
#                     Table B records (88B each + 0xFFFFFFFF separator)
#                       ★ +0x54 BE u32 = 'slot mask' (interpretation unsolved;
#                                                     varies between byte mask
#                                                     for some sections and
#                                                     float-shaped values for
#                                                     others)
#                       cull_box[0] f32 ≥ 80 = real instance, < 80 = streaming
#   [position table]  per-section instance_count × 96 B transforms:
#                     pos(12) + w=1.0(4) + section_constant(16) +
#                     up(12) + 4-byte pad + 3 rotation rows of (12+4-pad) each
#                     ★ all 16 'pad' bytes confirmed near-zero — no per-instance
#                       slot picker hides there.
#   [separator]       32 × separator_mult bytes between sections — actually
#                     contains LOD distance thresholds (e.g. 300, 2500, 220, 10).
#   [trailing VBUF]   79 × 40-byte records, anchor 0xe3 0xd0 at offset 32 of
#                     each. Currently treated as preview-vertex point cloud.
#                     ★ STRONGEST REMAINING CANDIDATE for the missing 5th
#                       placement store (golf cart, haybale, grandstand,
#                       BarrierBrand). Each chunk has one. Per-record fields
#                       beyond packed position not yet decoded.
